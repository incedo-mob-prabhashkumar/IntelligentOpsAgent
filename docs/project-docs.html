Project Title

AI IT Support Assistant (LangGraph + Streamlit + PostgreSQL + Ollama)

Problem Statement

Employees need fast help for common IT issues such as VPN access, ticket status, and new support ticket creation. The assistant must route intent, validate inputs, prevent duplicates, and provide clear responses.

Solution Overview

  • Stateful LangGraph orchestration with conditional routing.
  • Streamlit chat interface with business table output.
  • PostgreSQL-backed tools for knowledge, employee, ticket, and status operations.
  • Intent classification with local Ollama model and deterministic safeguards.
  • SentenceTransformer-based semantic retrieval with lexical fallback.

Setup Instructions

  1. Create venv and install dependencies.
  2. Run PostgreSQL and create it_support database.
  3. Load sample data using db/init.sql.
  4. Run Ollama and pull gemma4:latest.
  5. Create .env from .env.example.
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
psql -U postgres -d it_support -f db/init.sql
ollama pull gemma4:latest
streamlit run app.py

Environment Variables

  • OLLAMA_BASE_URL (default http://localhost:11434)
  • OLLAMA_MODEL (default gemma4:latest)
  • POSTGRES_DSN (example postgresql://postgres:postgres@localhost:5432/it_support)
  • SHOW_TRACE (optional, true to show trace)

Sample Inputs and Outputs

Input: How do I reset my VPN password?

Output: KB-guided response with article reference (for example KB-001).

Input: What is the status of my laptop issue? EMP1024

Output: Latest ticket status with structured table output.

Input: My VPN is not working. Please raise a ticket. EMP3001

Output: Ticket creation confirmation with generated ticket ID.

Key Design Decisions

  • Rule-first routing plus LLM fallback for robustness.
  • Stateful workflow via employee and pending intent memory.
  • Validation gates before all write actions.
  • Grounded responses tied to tool output.

Limitations

  • Intent classifier can be improved with richer evaluation.
  • Authentication and authorization are out of local demo scope.
  • Ticket ID generation is basic for local usage.
