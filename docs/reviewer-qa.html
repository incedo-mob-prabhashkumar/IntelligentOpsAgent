Project Summary

This project is a stateful AI IT support assistant built with Streamlit, LangGraph, PostgreSQL, Ollama, and semantic retrieval. It helps employees ask IT questions, look up knowledge, check ticket status, and create or update tickets safely.

The Q&A below is written in reviewer-friendly language so you can explain the project clearly during evaluation.

LangGraph, Tools, and State Management

Question: How is LangGraph working in this project?

LangGraph is the workflow engine of the assistant. It takes the user message, captures context, decides the intent, validates required fields, and routes the request to the correct node. It helps the app handle multi-step IT support conversations instead of treating each message as isolated text.

Question: How is LangGraph helping here?

It helps by making the assistant controlled and stateful. The graph can pause for missing information, remember earlier user input, switch between knowledge search and ticket workflows, and make sure write actions only happen after validation. That makes the assistant more reliable than a plain prompt-based chatbot.

Question: What tools are used in this project?

The assistant uses a knowledge search tool, employee lookup tool, ticket lookup tool, ticket creation tool, ticket update tool, and system status tool. These tools connect the AI workflow to the local PostgreSQL data and return structured results for the UI.

Question: Where is state management happening and how?

State management happens inside the LangGraph state object and the service flow. The state stores values such as user input, intent, employee ID, ticket ID, pending intent, missing fields, tool result, and final response. Each node in the graph reads from and writes to this shared state so the assistant can continue the same conversation across turns.

Why Streamlit?

Question: Why did you use Streamlit in this project?

Streamlit is used because it lets me build a clean chat-based user interface quickly in Python. It is simple to run, easy to demo, and ideal for showing AI workflow results, chat history, and structured table outputs without building a full frontend stack.

Question: What is the advantage of Streamlit for a capstone project?

It reduces UI complexity, speeds up development, and keeps the whole project in one language. That makes it easier to focus on the core AI logic, routing, validation, and database integration.

Why SentenceTransformer?

Question: Why did you use SentenceTransformer for knowledge search?

SentenceTransformer helps the assistant understand meaning, not just exact words. If a user says "VPN not connecting" and the knowledge article says "VPN authentication issue," semantic embeddings can still match them. That gives better results than keyword search alone.

Question: Why not use only keyword matching?

Keyword matching is too rigid. Users describe the same problem in different ways, so semantic search improves relevance. The system still keeps a lexical fallback, so if embeddings are unavailable the app can still return useful results.

What is state management?

Question: What is state management in this app?

State management means keeping important conversation information across multiple user turns. In this app, the state stores values like employee_id, pending_intent, proposed_issue_summary, missing fields, tool results, and the final response.

Question: Why is state management important here?

Because the assistant often needs multiple steps to complete one task. For example, the user may first mention a VPN issue, then later provide their employee ID. The state helps the assistant remember the earlier message and continue the same workflow instead of starting over.

State Management Flow

How does the app work end to end?

Question: Walk me through the full flow of the application.

The user sends a message in Streamlit. The service layer sends the message to LangGraph. The graph captures context, decides the intent, validates the inputs, runs the right tool from the tool layer, reads or writes PostgreSQL if needed, and then uses grounded tool output to generate the final response. Streamlit then shows the answer and any table output.

Question: What makes the response trustworthy?

The assistant does not invent ticket details. It uses validated tool output from the database and knowledge base, then formats that output into a user-friendly response.

More Reviewer Questions on LangGraph and State

Question: Why did you choose LangGraph instead of a single LLM prompt?

Because the project needs workflow control, not just text generation. A single prompt cannot reliably manage ticket lookup, ticket creation, validation, memory, and tool routing. LangGraph lets me split the problem into nodes with clear responsibilities.

Question: How does the assistant know which tool to call?

The intent decision node checks the message and context, then routes to the appropriate tool path. For example, a VPN help question goes to knowledge search, a ticket status request goes to ticket lookup, and a ticket issue request goes through validation before ticket creation.

Question: How does the state help with follow-up questions?

If the user forgets to provide employee ID or issue summary, the assistant stores the pending request in state and asks a follow-up question. When the user replies later, the graph uses the stored state to continue the same workflow without losing context.

Question: What happens if the assistant switches topics mid-conversation?

The intent node re-evaluates the new message while still keeping the conversation history in state. That means the assistant can either continue the previous task or start a new one depending on the user’s latest input and the current pending state.

Question: Where are the tools implemented?

The tools are implemented in the local tool layer of the project, mainly in src/tools.py, and they use PostgreSQL-backed data from the models and database layer.

Question: How does the state object move through the app?

The service layer sends the message and current context into the graph. The graph updates the state at each node, and the final node returns the response plus any structured tool result back to Streamlit.

A: The graph keeps a shared state object that stores values like employee ID, ticket ID, pending intent, missing fields, tool result, and final response. Each node reads and updates this state so the assistant remembers the conversation.

A: Validation prevents bad writes. The assistant checks for required fields, employee existence, duplicate tickets, and valid ticket IDs before it creates or updates records in the database.

A: Before creating a ticket, the assistant checks open or recent tickets for the same employee and similar issue text. If a matching issue already exists, the assistant stops the duplicate and explains the reason to the user.

A: If the user omits something important like employee ID or issue summary, the assistant stores the pending task in state and asks a follow-up question. Once the user provides the missing value, the same workflow continues.

Q: How does the project stay grounded?

A: It uses tool output from the knowledge base and database instead of guessing. The final response is generated from validated results so the assistant does not invent ticket IDs or status values.
