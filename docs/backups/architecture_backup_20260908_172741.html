Architecture overview

AI IT Support Assistant

A stateful support assistant for employee help requests, ticket operations, knowledge lookup, and system-status checks. It combines a Streamlit chat frontend, a LangGraph orchestration layer, and local or remote model routing with grounded business tools.

LangGraph Streamlit PostgreSQL Ollama SentenceTransformer

System overview

The application is designed to understand IT support requests in natural language and safely route them to the right action. It supports knowledge lookup, employee lookup, ticket lookup, ticket creation, ticket update, and system-status checks.

This architecture keeps the assistant grounded in local business data, validates write actions before execution, and retains conversation state across turns.

End-to-end request flow

  1. User submits a message in the Streamlit chat.
  2. app.py passes the request and context to the agent service.
  3. ITSupportAgent.handle_message invokes the LangGraph workflow.
  4. Context capture and intent detection route the message to the correct tool or response branch.
  5. Validation checks are run before ticket writes or updates.
  6. Structured tool result data is returned to the UI for display.

Routing and intent strategy

The assistant uses a hybrid strategy:

  • Deterministic checks for critical cases such as ticket IDs, confirmation states, and update rules.
  • Semantic intent classification to support natural-language requests.
  • Safe fallback behavior when meaning is unclear.

Current routed intents include:

  • knowledge_search
  • employee_lookup
  • ticket_lookup
  • ticket_creation
  • ticket_update
  • system_status
  • small_talk

Safety and validation controls

  • Missing required fields are checked before ticket creation or updates.
  • Employee record existence is validated before attempts to create tickets for that employee.
  • Duplicate-check logic reduces repeat ticket creation using recent open-ticket similarity.
  • Ticket updates require a valid existing ticket ID.
  • Data access remains grounded and guarded against invented facts.

SentenceTransformer and model behavior

The semantic retrieval path converts the user query and knowledge article text to embeddings, then ranks them by similarity. This helps the assistant understand paraphrased user language and improves relevance versus strict keyword matching.

When semantic retrieval is unavailable or low confidence, the app falls back to lexical matching to keep the experience reliable.
