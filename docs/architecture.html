AI IT Support Assistant

A stateful support assistant for employee help requests, ticket operations, knowledge lookup, and system-status checks. It combines a Streamlit chat frontend, a LangGraph orchestration layer, and local or remote model routing with grounded business tools.

System Overview

The AI IT Support Assistant is a grounded support workflow for employee issues, ticket requests, knowledge lookup, and service health checks. It combines a Streamlit chat interface, a LangGraph orchestration layer, and a tool layer connected to PostgreSQL and knowledge content.

  • Natural-language understanding for help requests and issue triage.
  • Deterministic validation for ticket IDs, employee IDs, and pending confirmations.
  • Semantic routing using sentence-transformer similarity before heuristic fallback.
  • Structured responses with tool output rendered in a user-friendly format.

Runtime Components

  • UI: Streamlit app in app.py
  • Service: ITSupportAgent in src/service.py
  • Workflow: LangGraph orchestration in src/agent_graph.py
  • Intent layer: semantic classifier and response logic in src/llm_router.py
  • Tools: employee, ticket, knowledge, and status access in src/tools.py
  • Database: PostgreSQL layer via src/database.py and src/models.py
  • Configuration: environment-driven model selection in src/config.py
  • State: multi-turn context and pending actions managed in src/state.py

Request Flow

  1. User enters a message in the Streamlit chat UI.
  2. The service layer forwards the request and context to the LangGraph workflow.
  3. Intent detection chooses between knowledge lookup, employee lookup, ticket actions, or status checks.
  4. Validation rules run before write operations to reduce duplicates and invalid updates.
  5. Structured outputs are returned to the UI and displayed for the user.

Routing Strategy

Intent resolution follows a layered strategy: exact deterministic matches first, then semantic sentence-transformer similarity, then keyword-based heuristic fallback, and finally a safe small-talk response.

  • knowledge_search
  • employee_lookup
  • ticket_lookup
  • ticket_create
  • ticket_update
  • system_status
  • small_talk

Safety and Validation

  • Missing employee IDs and ticket IDs are confirmed before performing write actions.
  • Duplicate ticket checks reduce repeated or redundant reports.
  • Database validation ensures created and updated records align to schema requirements.
  • Grounded responses avoid making up unavailable facts or unsupported actions.

Data Domain

  • employees: workforce records and identifiers
  • tickets: support cases, priorities, and workflow state
  • knowledge_base: policy and troubleshooting data
  • system_status: service health and operational conditions
